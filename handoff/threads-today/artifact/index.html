Threads, as they show today

The five kinds of thread you named, drawn by Homeroom's own pages as of main d5db478 (with #6057, the bot page redesign). Each one is a real thread in a local copy of the platform, seen by an ordinary member, on a 1280px window and a phone.

Fake people, fake requests, all "Staging demo". How they were made is at the end.

What stands out

  1. BugA private thread opened from the bot page on a desktop splits the 400px Main Chat column into the chat and the thread side by side, so both wrap a word or two a line. See 1.
  2. Two pagesA thread with a change has two pages: the request's and the change's, each with its own head, votes and Mute. The change page points back ("Conversation lives on #6062", "In this thread"). From the bot page, a vote opens the change page, not the thread. See 4.
  3. PlansA plan shows twice on the request page: a card under the request, and a "posted plan v1 · Read" line among the replies (which the "2 replies" count leaves out). See 4.
  4. PlansWith two plans and two changes, the request page lists the plans, then changes A and B, with nothing saying which plan each change was built from. Only the change page shows its plan. See 5.
  5. VotesThe A/B vote reads 0 · 0 · 0 though A has one Yes and B two. None are from approvers; the single change's card says such votes don't count, the A/B card doesn't. And change A's own page shows two Votes cards: the A/B vote, and A's own with its own Vote button and "Needs 1 more yes". See 5.
  6. NamesOn the Messages screen the same chat is "Main Chat" in the header and "Homeroom bot · Builds what you ask for" over the conversation. See 1.
  7. StatusOnly the request with nothing built shows the Asked · Plan · Built · Voted in steps. Once a change is up, the change's row takes their place, so the request no longer says where it is in those steps. See 2 and 3.

5 · #6066 A dark theme

ana planned "Follow the system setting" and dewi "A switch in Settings"; each built theirs, #6067 and #6068. With two changes up for one request, it is a pick between them.

  • "Pick one" beside the number. Two plan cards, then "2 changes for #6066" as rows A and B, each with its author, number and checks.
  • One Votes card for both: A, B and Neither, with "The first to pass Homeroom's approval rule goes live, and the others close. Neither counts as a No on each."
  • Nothing pairs a plan with its change: "Follow the system setting" is A, "A switch in Settings" is B, but you'd have to read the titles to know.
  • Change A's page carries its plan, then "In this thread" with the request and change B, then the same A/B vote as the request.
  • Under that is a second Votes card, A's own: "Needs 1 more yes", "1 yes so far is from someone who isn't an approver", and its own Vote button. So there are two ways to vote on A here, and the two cards count differently.

How these were made

  • Homeroom at main d5db478, run in this session on a fresh database in staging mode, signed in as usernode-capture: a member of the Homeroom project, not an admin.
  • Requests were filed through the platform's request service with the twin row its filing route writes; plans were posted through the same service Homeroom's post_spec uses; changes, votes, replies and the private thread are rows shaped as the platform's own staging seeds write them. Numbers start at #6061, near Homeroom's real ones.
  • One stand-in: a staging copy fills a request with no comments with "[Mock]" ones, so the screenshots got production's answer instead, an empty list.
  • Not shown: change previews, before & after shots and Homeroom bot's own posts, which need the platform's builders. On the phone, the "Get the app" bar is what a phone browser shows.
