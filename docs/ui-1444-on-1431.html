The App Chip Takes the Header

#1444 sits directly on top of #1431 — its parent commit is #1431's merge, with nothing in between. Under three hours of main separate them, and in that window the header lost four controls, the menu behind the one remaining control gained six destinations, and three of #1431's own decisions were argued back. This is each change and the reason recorded for it.

One control names where you are, and its menu lists everywhere you can go. A destination with its own page belongs in that menu; nothing else does.

frontend/src/features/header/app-switcher-chip.tsx

Everything in #1444 follows from that one sentence. Every header slot the shell had grown over the years — a hamburger, a home glyph, a messages bubble, an app-mode switch — was some version of answering the same question a second time, in a second place, with a second glyph. #1431 built the control that answers it properly and then gated it. #1444 removes the gate, and the rest falls out.

01

The bar, before and after

Both mocks are a root screen — Home, Discover, Settings — where the difference is sharpest. Inside an app, #1431 did render a tappable title tab; outside one, it did not.

#1431 — after the Streamlined Concept landed
⌂ Home 💬 🔔 Improve

A 28px slot holding a house glyph or a back arrow, an inert <h1> with no chevron and nothing behind it, then a chat bubble, the bell and the pill. The title tab existed, but was gated on target && slug.

#1444 — the chip is the label everywhere
Home ▾ 🔔 Improve

The left group collapses when it holds nothing, so the chip sits flush at the header's own 16px padding. Two controls on the right, one of them filled. On a dev session the chip does not render at all: that bar is ← plus the status pill, with the change's name in the strip below — #1431's behaviour, kept.

02

The left group empties out

Three deletions, and one invariant that gets simpler because of them.

Retired

The house glyph, #back-icon-home

Home is a row of the chip's menu, reachable from every screen, so a house icon an inch to the chip's left was the second control answering one question.

The consequence is the more interesting half: with one child left, #back-btn means exactly one thing — back a level — so the chevron's className becomes a constant and the anchor's own hidden is the whole of the visibility state. One node toggles now, not three, in React and in setBackIcon's pre-hydration fallback alike.

Retired

The reserved 28px slot

The fixed box existed to stop a centred title shifting as the anchor came and went. The chip is flush left, so all the box did was reserve an inch of dead space at the top-left of every root screen.

Measured rather than assumed: the header's own gap-3 applies to an empty-but-present flex item, so the chip started at x=28 instead of the header's 16px padding. That was the "extra space for an icon that isn't used". The group now collapses to hidden when it holds nothing.

Measuredchip x=28 → x=16 · bar height 52px, unchanged
Retired

The chat bubble and the app glyph

#messages-btn goes because Messages is a destination with its own page, and by the rule those live in the menu. header-app-icon.tsx goes because a chip that carries the app's name does not need a second picture of the same app beside it.

A commit that ships red on purpose

The commit doing this work names its eight failing assertions up front and leaves them failing, because the fixes belong to later commits in the same branch. One is singled out as not bookkeeping: header-height-parity pins a 28px floor on the wrapper being deleted, and its expectation is held back until the bar's height has actually been checked on a screen with the anchor hidden. "A header that changes height between screens would be a worse bug than the dead space removed here."

03

The chip: one gate removed

#1431 built the store, the publish seam, the chevron and the sheet behind it. The whole of #1444's structural change is deleting the condition on when that control renders.

Ungated

#header-title-tab becomes #app-switcher-btn

#1431's tab rendered only inside an app, so Home, Discover, Messages and Settings kept an inert <h1> and the sheet behind it could not even open.

The argument for dropping the gate, from the component's own header comment: "A control that is sometimes a control is worse than either — you cannot learn 'the name at the top is how you get around' from a thing that is a label four screens out of five."

What is deliberately unchanged is as load-bearing: the <h1> and its className are byte-identical to what #1431 shipped, and the class stays a constant prop, because use-header-layout.ts toggles .is-centered on that node through classList and a re-rendered class attribute would drop it.

Added

A named label, #app-switcher-name

The label was a bare <span>, so a declared check could assert that the chip exists but not what it says. It is a named slot now, and a check reads it.

Fixed

The chip reports its menu's state

#improve-btn — the other panel trigger in this bar — has carried aria-expanded since #1412, so this was the shell's own convention rather than a nicety, and #1431's title tab never had one.

It reads appContextStore instead of being written onto the node by the controller, and that is the point: the sheet closes three ways — the trigger, the backdrop, Escape — and an attribute only the trigger's own handler maintains goes stale on the other two.

Verifiedfalse → true on tap; back to false on Escape and on backdrop dismiss
Corrected mid-branch

The chip has no avatar

It carried the viewer's avatar for one round. The chip names the app you are in, and a picture of you inside it answers a different question — Profile is a row of the menu behind it. applyUserAvatar goes back to the one pair it has left, Home's account row.

04

The menu grows the platform destinations

#1431's sheet is kept whole — lifecycle, app strip, Create New. What it gains is everywhere the retired header slots used to point.

Grew

Home · Discover · Messages | Profile · Settings · Admin

Six destinations in two groups, over the strip of the viewer's apps. Its "Platform" section label went with the app group it existed to separate from.

Every row keeps the writer it had elsewhere: #switcher-row-messages carries #drawer-messages-badge with its writer unchanged, settings.js still publishes the BYOK flag for #switcher-byok-dot, and #switcher-row-admin ships hidden behind the same renderAdminButton gate. Only the parent changed.

Kept horizontal

The app strip stays a rail, and that is the scroll fix

A superseded branch (#1436) made the apps a vertical list. With 39 apps that ran to roughly 1,800px inside an 844px panel, clipping Home through Settings with no scroller to reach them.

A horizontal strip is vertically bounded, so 39 apps occupy the space 2 do and nothing below can be pushed anywhere. #switcher-nav is the menu's only vertical scroller, which is why the clipping bug cannot recur in this shape.

05

Three of #1431's calls argued back

None of these is a taste reversal. Each names the premise that changed underneath the original decision, which is what makes it reviewable.

Reversed

Messages is a screen again

#1431 made it #messages-sheet for a real reason: a chat bubble sat in the header on every route, so a full-screen Messages had no honest answer to "back to where?"

The bubble is gone and Messages is a menu row, so the reasoning is gone with it — and reading past conversations and sending from them is a place you go, which is how every messaging product models it. sheet-controller.js and sheet-store.js are deleted; #messages-screen comes back as the root.

Restored

The Improve panel's reference footer

#1431 dissolved the block and rehomed each fact separately: the GitHub link to the app's own page, the versions to a new Settings About block, fork lineage to the app detail page.

The verdict on that: "every move was defensible alone; the sum meant leaving the app to read facts about the app you were standing in." The footer comes back with the GitHub link, the app's version, the platform build and the native app version, and Settings' About block — built to hold two of these rows — goes with them. refreshDeployDot rescopes to #improve-footer.

Fork lineage does not come back: #browse-detail-fork is the better home, because lineage is a fact about an app rather than about the panel you have open.

Returned

App / Board / Activity stay in the Improve panel

They spent one round of this branch as menu rows, on the argument that they are destinations and destinations live in the menu.

That was reversed within the branch: "the consistency argument was real but it was the weaker one — the menu answers WHICH APP, and those three answer WHICH PART OF IT, which is the question the panel you open from inside an app is already about." #improve-views, ContextRow and two declared checks go back exactly as #1431 had them.

Why the log will look like a revert, and isn't

#1431 had already reversed one of its own owner reviews — Improve went from a plain violet text action back to a filled pill — and it left a commit whose only job is to say why, because git log -S lands anyone who searches on the review that says the opposite. The deciding fact was a date the repository does not record: the Figma board is newer than the review, and the bar the review was written about no longer exists. #1444 inherits that pill unchanged.

06

One event, one badge

Changed

A direct message stops lighting two counters

conversation_message is a notification kind, so one incoming DM raised the bell's unread count and the Messages unread sum — one event, two badges, in two colours.

It is subtracted from the bell for the same reason session notifications already were: the count belongs to whichever surface you would actually go to. The Messages row's count is the better one — it is per-conversation, it survives the notification being marked read, and it is what you tap to act on.

The subtraction is clamped with Math.max(0, …), and the comment says why: both splits read the loaded items page while unread is the server's total, so on an account with more unread than one page holds the subtraction can overshoot — and a negative badge is worse than an undercount.

07

Bugs found on the way

Two were found by building the thing and looking at it; one was reported on main and would have shipped; two were the branch's own checks, written wrong.

Fixed

The header's controls had been invisible in light mode

The chip's first surface was bg-zinc-100, the same token the bell and #back-btn use, and it rendered invisible. tailwind.config.js overrides the ramp: zinc-100 there is #eaeaea, which is exactly the light page ground.

So the chip had a surface you could not see — and so, it turned out, had the bell and the back button, for as long as that reskin has been in. In light mode the bar was three bare glyphs on nothing. All four surfaces move to zinc-50 (#f5f5f7), which lifts off the ground; dark mode was always fine at zinc-800 on zinc-950 and is untouched.

Verifiedscreenshotted in both themes rather than reasoned from the classes
Fixed

Improve never reached the margin the shell aligns to

The pill carried mr-2.5 from when it had siblings to its right. As the last control in the bar that was 10px of dead space between it and the header's own px-4 edge. The bell's mr-1 was the same mistake one control earlier, and became trailing space whenever Improve was hidden.

Both margins are gone and the right group carries gap-1: spacing belongs to the layout, not to the last child.

MeasuredImprove right edge 364 → 374 · content edge 374
Fixed

A staging preview with no way out of it

Reported on main, and it would have shipped: a staging preview opened outside a dev session had no exit control at all.

Under-chrome mode — the preview sitting below the header and the session strip — deliberately removes both of the overlay's own exits, because the strip's pencil segment is the way back. That is sound only while the strip is on screen, and the class was gated on previewActive alone, which is published for every preview from a session or not.

Two guards, because either alone is one owner's agreement away from the same dead end: the class is gated on the session route as well as the flag, and the CSS refuses to hide the last exit unless the strip is really in the document (body:has(#dc-session-header)). "Hiding the only way out is worth making structurally impossible rather than conditional on two owners agreeing."

Verifiednew test confirmed to FAIL with either guard reverted, not merely to pass
Fixed

Two declared selectors that could not have matched

*:has(#improve-sessions) never matched, because #improve-sessions is a direct child of #improve-body and :has needs a descendant. And #app-switcher-btn ~ #notifications-btn could not join the chip, which lives inside #header-title, to the bell in the right group: they are not siblings.

The existing guard could not have caught either. dapp-selectors-resolve proves that every id in a selector still exists, deliberately, because most of these selectors only match with data loaded. A selector whose ids are all real but whose combinators are wrong costs a full check cycle to discover — recorded as worth its own request rather than fixed as a rider on this one.

08

Bookkeeping that isn't optional

  • Every id change is recorded in RETIRED_IDS / ADDED_IDS with its reason, and the frozen markup baseline is untouched — the repository's rules forbid refreshing it to go green.
  • Twelve declared checks are repointed and two added: the menu's order, and its destination pair.
  • Tests that encoded #1431's shape are updated to the new one rather than relaxed. header-height-parity now asserts the 28px floor — the invariant that survives the deleted wrapper — and keeps the fixed-width rule on #landing-header, where a centred title still needs it.
  • The branch opens with a separate housekeeping commit: three unit tests were already failing on main before #1431 merged. Four em dashes are rewritten ahead of the guard that landed after the branch was cut, and one exact-class assertion is loosened to tolerate the layout utilities a different PR added beside the gate it protects — "what the test protects is the gate, not the flex utilities beside it." The finding it records is the more interesting one: the declared checks gate merge and the repository's unit suite does not.
